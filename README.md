## Web 端如何使用本仓库

1. 先阅读本入口及当前任务引用的项目文档，注明实际读取的分支或提交版本；无法确认版本时说明限制，不声称已获取最新状态。
2. 区分已核实事实、推断、计划、待验证和阻塞。仓库中的核验结论是本地监督者在记录时间获得的证据，不能描述成 Web 自己直接检查到的实时状态。
3. 按用户指定的当前任务核对目标、前提、约束及验收标准，再逐步指导用户操作；不要因看到路线图或待办就默认开始全部任务。
4. 仓库描述了本地服务器访问能力，不代表 Web 也具备该能力。缺少执行所需信息时，明确说明缺口；涉及公网地址或凭据时使用占位符，让用户在自己的环境中替换，不要求将真实值发布到仓库。
5. 根据用户返回的真实输出判断结果。发生失败、证据不足或与仓库矛盾时，明确记录差异，不将方案当作已执行操作，也不自行假定问题已解决。
6. 完成当前任务后，提供可交回本地监督者的脱敏结果：任务标识或目标、实际执行的操作、关键验证输出及时间、涉及的变更、遗留问题和建议。区分执行验证结论与本地监督者的最终验收。

本地监督者收到结果后，结合已授权的只读检查进行验收，维护项目事实并提交、推送更新。Web 无需承担本地仓库维护职责；新会话通过仓库获取已发布的上下文，无需依赖其他会话的聊天历史。

任务 001 和任务 002 的基础范围已完成，目前推进任务 003 的只读核查，尚未发布 Web 修改任务。DDNS 仍在另行调试，待用户交接后再验收；Web 先读取当前状态，按用户指定的任务执行，不因基线完成而认定 DDNS 或备份恢复已经成功。

## 仓库边界

本仓库保存有效的项目事实、技术决策、任务及经过脱敏的必要证据；不用于服务器配置同步或部署。

不保存凭据、私钥、环境文件、运行数据、数据库、上传文件、备份或原始日志。必要的配置片段和验证摘要需经过脱敏，并注明来源与时间。

## 公开信息边界

本仓库公开可读，以下规则同样适用于文件内容、提交说明、任务记录及验证证据：

- 可以记录：内网 IP、架构、任务、技术决策，以及经过审查和脱敏的配置。允许保存配置不代表允许保存其中的所有值。
- 不得公开：服务器真实公网 IPv4 / IPv6 地址、密码、私钥、访问密钥、Token、会话 Cookie、恢复码，以及包含凭据的连接字符串或 URL。
- 配置及命令输出中的公网地址使用 `<PUBLIC_IP>` 等占位符，凭据使用 `<REDACTED>` 或环境变量引用。截图、域名及连接信息也需检查是否暴露上述内容。
- 未脱敏材料不进入公开仓库，也不在提交说明中引用真实敏感值。忽略规则不能替代内容审查。
- 提交前检查暂存内容，推送前检查全部待发布提交；删除当前文件中的敏感值不能消除历史中的泄露。

公开任务说明应包含 Web 执行所需的完整上下文，不依赖本地私有文件。文档按实际需要逐步增加。
