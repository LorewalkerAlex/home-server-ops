# 002：历史交接核查与基线建立

状态：非特权核查已完成，完整验收待用户提供管理员检查结果。发起日期：2026-10-21。执行与验收主体：本地 Codex；需管理员权限的命令由用户执行。

## 目标与范围

根据用户转交的 Web Project 历史摘要，与服务器当前证据交叉核对，建立可供后续 Web 会话使用的状态基线。仅进行读取，不修复 Caddy、不变更 DNS、不调整防火墙、不重启服务、不执行磁盘写入。

## 已完成的核查

- 使用已授权的专用普通账号读取系统、磁盘和挂载、运行中服务、监听端口、可读配置，以及匿名 HTTP 页面和静态资源。
- 在本机 Windows 只读核查指定的历史临时防火墙规则、内网地址和代理端口监听；从服务器验证代理端口 TCP 可达。
- 已确认 `/srv/persistent` 位于系统盘、Docker 数据盘另为约 500GB SSD；补齐了原历史摘要中的存储信息缺口。
- 已确认 Caddy 重定向修复和 LAN 来源限制存在，匿名登录页及 8 个静态资源成功响应；原先“前缀丢失待修复”的历史状态已过期。登录后流程仍未验收。
- 已核实事实、证据范围及历史计划汇总于 [服务器当前状态](../docs/current-state.md)。

## 待用户执行的管理员检查

检查脚本：[002-admin-readonly.sh](../checks/002-admin-readonly.sh)。请在 Ubuntu 的现有管理员会话中查看并执行其内容；任一步失败时停止并回传错误，不尝试修复。脚本不输出环境变量、完整容器 inspect、秘密配置内容或数据库内容。

| 检查 | 原因 | 验收重点 |
|---|---|---|
| UFW 实际规则 | 普通账号只能读取默认配置 | 实际入站范围、IPv6 规则、是否存在未知放行；不能仅凭 UFW unit active 认定安全边界成立 |
| Docker ps / 选择性 inspect | 普通账号无 Docker 套接字访问权 | 三个应用实际镜像、状态、健康检查、网络、端口、重启策略和挂载是否与历史及配置声明一致 |
| Docker info 选择性字段 | 配置文件不等于运行时状态 | data-root、存储驱动、snapshotter 信息和实际代理是否符合预期 |
| DDNS 配置 stat | secrets 目录不可进入 | 文件存在及权限，不读取或回传凭据 |
| Tududi 数据库目录元数据 | 应用数据目录不可进入 | 数据库与备份文件是否存在；只验收存在性，不验收恢复能力 |
| Netplan 安全摘要 | 配置文件仅 root 可读 | 固定 IPv4 和默认网关是否写入持久配置；公网地址不回传 |

脚本输出如意外出现公网地址、凭据或需脱敏域名，先替换为占位符再发送。输出将由本地监督者审查后选择性写入公开记录。

## 仍需单独提供的证据

- 路由器当前端口映射和远程管理状态，不能通过服务器现有只读权限完整判断。
- DDNS 实际记录类型、TTL、有效 RAM 权限范围；域名和公网记录值不公开。
- 最近一次自动更新成功的时间及脱敏结果，并独立确认 DNS 解析值是否等于家庭当前公网 IPv4。人工 API 测试、DNS 恰好相等或 UI 可访问均不能单独证明自动更新成功。
- 如需将 DDNS 管理入口标为完整可用，需用户验证真实登录及登录后功能；本轮仅有匿名页面和资源检查。

以上不要求立即修改任何设置。先审查本次管理员输出，再针对剩余信息缺口准备独立检查。
